# RSS News Bot

Телеграмм бот, который собирает новости из RSS лент. Каждый пользователь подписывается на свои ленты и получает свежие записи.

## Задача 2:

**Цель:** Добавить команды: /add \<url>, /remove \<url>, /list, /latest \<url>, /pagesize \<n>. Сделать так, чтобы бот вёл отдельные диалоги с разными пользователями, а хранение данных было отдельно от логики бота.

Чтение ленты вынесено в отдельный класс, тесты работают на локальных XML-файлах без интернета. Команда /latest показывает новости страницами: бот выводит первую страницу и кнопку "Показать ещё", по нажатию показывается следующая. Команда /pagesize задаёт размер страницы (по умолчанию 3). Размер страницы и текущая позиция чтения хранятся отдельно для каждого пользователя.

### Примеры:

#### Пример 1. Обычная работа

П: /add https://habr.com/rss

Б: Лента добавлена

П: /list

Б: 1. https://habr.com/rss

П: /remove https://habr.com/rss

Б: Лента удалена

#### Пример 2. Два пользователя

П1: /add https://habr.com/rss

Б: Лента добавлена

П2: /list

Б: Подписок пока нет. Добавь ленту командой /add \<url>

#### Пример 3. Ошибки

П: /add

Б: Укажите ссылку: /add \<url>

П: /add habr

Б: Не удалось найти рассылку

П: /add https://habr.com/rss

Б: Лента добавлена

П: /add https://habr.com/rss

Б: Эта лента уже есть в списке

#### Пример 4. Новости по страницам

П: /latest https://habr.com/rss

Б: 1. Вышла новая версия Java — https://habr.com/...

2. Как устроен RSS — https://habr.com/...
3. Telegram-боты на Java — https://habr.com/...

[Показать ещё]

П: (нажимает «Показать ещё»)

Б: 4. Паттерны проектирования — https://habr.com/...

5. Тестирование в JUnit — https://habr.com/...
6. Работа с XML — https://habr.com/...

[Показать ещё]

(когда новости закончились)

Б: Больше новостей нет

#### Пример 5. Размер страницы

П: /pagesize 2

Б: Размер страницы изменён: 2

П: /pagesize 0

Б: Размер страницы должен быть числом от 1 до 20

## Задача 3:

**Цель:** Сделать диалог добавления ленты из нескольких шагов и перенести хранение в базу данных. Команда /add без ссылки запускает диалог, и бот помнит, на каком шаге находится каждый пользователь: ждёт ссылку или ждёт название. Шаг диалога хранится отдельно для каждого пользователя и не зависит от телеграмма.

**База данных:** Данные пользователей (ленты с названиями, размер страницы, позиция в ленте, состояние диалога) хранятся в базе данных PostgreSQL и не пропадают после перезапуска бота. Для этого написана новая реализация интерфейса хранилища, а логика бота не менялась. Тесты хранилища работают на базе данных в оперативной памяти (H2 в режиме PostgreSQL), поэтому не создают файлов и не зависят друг от друга.

### Примеры:

#### Пример 1. Обычный диалог

П: /add

Б: Пришлите ссылку на ленту

П: https://habr.com/rss

Б: Лента найдена. Как её назвать?

П: Хабр

Б: Лента “Хабр” добавлена

П: /list

Б: 1. Хабр — https://habr.com/rss

#### Пример 2. Ошибка и отмена

П: /add

Б: Пришлите ссылку на ленту

П: habr

Б: Не удалось найти рассылку. Пришлите ссылку ещё раз или /cancel

П: /cancel

Б: Добавление отменено

#### Пример 3. Данные сохраняются после перезапуска

П: /add https://habr.com/rss

Б: Лента добавлена

(перезапуск бота)

П: /list

Б: 1. https://habr.com/rss

#### Пример 4. Неверное название

(лента «Хабр» уже есть в списке)

П: /add

Б: Пришлите ссылку на ленту

П: https://example.com/rss

Б: Лента найдена. Как её назвать?

П: Хабр

Б: Лента с таким названием уже есть. Пришлите другое название или /cancel

П: Пример

Б: Лента “Пример” добавлена

П: /cancel

Б: Нечего отменять

## Запуск

Нужны JDK 25, Maven и PostgreSQL.

1. Создайте базу данных в PostgreSQL, например:

   ```sql
   CREATE DATABASE rss_bot;
   ```

   Таблицы бот создаёт сам при первом запуске.

2. Создайте в корне проекта файл `.env` (он не попадает в git):

   ```
   BOT_TOKEN=токен бота от @BotFather
   DB_URL=jdbc:postgresql://localhost:5432/rss_bot
   DB_USER=postgres
   DB_PASSWORD=пароль пользователя базы
   ```

   Порт в `DB_URL` должен совпадать с портом, на котором запущен PostgreSQL (по умолчанию 5432).

3. Запустите бота из корня проекта:

   ```
   mvn compile exec:java
   ```

Тесты запускаются командой `mvn test`. Для них PostgreSQL не нужен: хранилище проверяется на базе H2 в оперативной памяти.
